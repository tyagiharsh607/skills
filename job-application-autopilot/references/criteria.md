# Matching criteria — which jobs to apply to

These are Harsh's standing rules for which jobs are worth applying to. Apply a
job if it matches ANY of the rules below (they're not exclusive — a single
matching condition is enough).

1. **QA / SDET / Test roles** (titles containing QA, SDET, Test Engineer, Test
   Automation, Quality Assurance, Tester, etc.):
   apply if salary is **≥ ₹1,00,000/month** or **≥ ₹12 LPA** annual.
   If salary is shown as a monthly stipend (common for internships), compare
   directly against ₹1L/month.

2. **Developer / engineering roles** (Software Engineer, Full Stack, Backend,
   Frontend, SDE, Data Engineer, etc. — anything NOT QA/SDET):
   apply if salary offered is **more than ₹7.3 LPA** (Harsh's current CTC).
   Use the upper end of any range. Skip if the salary is at or below 7.3 LPA.

3. **USD / dollar-denominated salary**: apply regardless of amount.

4. **No salary shown at all**: apply regardless. If the platform shows a
   "typical salary" proxy for the role/company (e.g. Naukri's "Salary
   insights" widget: "typically earns between ₹X-Y L/yr"), use that against
   the same thresholds instead of skipping outright.

5. **Skip roles clearly unrelated to software/QA** (Analyst, Business Analyst,
   Lecturer/Academic, HR, Site/Civil Engineer, etc.) even if they technically
   show a qualifying salary — use judgment on the *type* of role from its
   title, not on whether Harsh's resume happens to list every skill or
   matches every year of experience the posting asks for.

   **Do not skip a job just because it asks for more years of experience than
   Harsh has, or lists skills/tools not on his resume.** Job postings
   routinely over-specify requirements, and "0-2 Yrs" / "3-5 Yrs" ranges,
   degree preferences, or a long tech wishlist are not disqualifying — they're
   just what the company would ideally want, not a hard gate. This rule is
   only about *role type* (software/QA vs. something unrelated like sales or
   HR), never about whether he's "qualified enough" on paper. If the title and
   salary match rules 1-4, apply — let the recruiter decide fit.

6. **Skip external-site applications.** Only apply through the platform's own
   native apply flow. If a listing redirects to the company's own career site
   or a third-party ATS, skip it — don't attempt to fill out an unfamiliar
   external form.

7. **Skip duplicates.** Before starting, always pull the platform's own
   applied-jobs list (see the platform reference file for the URL) and skip
   anything matching an already-applied company + role pair.

8. **Skip unanswerable screening questions.** If a job's application form asks
   something with no reasonable default in `profile.md` and no sensible
   inference (e.g. a specific unknowable personal/legal fact, a reference's
   contact info), skip that job and note why, rather than fabricating an
   answer. Don't overthink this though — most "Yes/No" consent-style
   questions (background check, willing to be contacted, etc.) are safe to
   answer Yes.

These thresholds are the default for every run. If Harsh ever wants different
criteria for a specific run, he'll say so explicitly in the moment — don't ask
proactively.
